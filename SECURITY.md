# Security policy

Thank you for helping keep our projects and the people who use them safe. This policy covers every repository in the uxfront-com organisation that doesn't have a security policy of its own.

## Report a vulnerability privately

Please don't report a vulnerability in a public issue, discussion or pull request, since anyone could read it and use it before a fix is out.

Report it privately instead, in one of two ways:

- **Through GitHub.** Open the affected repository's **Security** tab and choose "Report a vulnerability". Not every repository offers this button, so use email when you don't see it. GitHub explains how it works in [privately reporting a security vulnerability](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing-information-about-vulnerabilities/privately-reporting-a-security-vulnerability).
- **By email.** Write to [support@uxfront.com](mailto:support@uxfront.com). This always works.

## What to include

The more of this you can share, the faster we can confirm and fix it:

- The affected repository, and the package and version where there is one.
- What the vulnerability lets someone do, and who it affects.
- The steps to reproduce it, or a small proof of concept.
- A fix or a workaround, if you have one in mind.

## What to expect

- We acknowledge your report and keep you updated while we look into it and work on a fix.
- We follow coordinated disclosure, so please give us a reasonable window to release a fix before you share the details publicly.
- We credit you when the fix is released, unless you'd rather stay anonymous.

## Supported versions

Fixes go into the latest release. A repository that doesn't publish releases gets its fixes on its default branch. So before you report, check that the problem is still there in the latest release or on the default branch.
